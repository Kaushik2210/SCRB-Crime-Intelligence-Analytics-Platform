# Deploying to Catalyst AppSail

Everything below the "Your steps" heading needs your Zoho account — CLI login and
project creation are interactive OAuth flows that can't be done from here.

## What's already in place (code side)

- [server.js](../server.js) — custom Express+Next.js server binding Catalyst's
  per-request SDK context, listening on `X_ZOHO_CATALYST_LISTEN_PORT`.
- [app-config.json](../app-config.json) — AppSail runtime config (`node18` stack,
  `npm run start`, build/predeploy scripts).
- `next.config.mjs` — `distDir: "dist"` per Catalyst's Next.js-on-AppSail guide.
- `package.json` — `start` script runs `node server.js`.

## Your steps

1. **Install the CLI** (if not already): `npm install -g zcatalyst-cli`
2. **Log in**: `catalyst login` — opens a browser OAuth flow tied to your Zoho account.
3. **Create a project** in the [Catalyst Console](https://console.catalyst.zoho.com) if
   you haven't, then from this repo's root: `catalyst init` — select the AppSail
   feature, point it at this directory, choose the `node18` stack. This generates
   `catalyst.json` (deliberately not committed by me — it encodes your local path and
   project link, generated by the CLI, not something to hand-write).
4. **Data Store**: create the tables listed in
   [docs/catalyst-datastore-schema.md](catalyst-datastore-schema.md) via the Console's
   Data Store page (or CLI table-creation commands) — match names/types exactly, since
   every `lib/*.js` ZCQL query references them by name.
5. **Auth for the seed script**: register a self-client at the
   [Zoho API Console](https://api-console.zoho.com/) scoped to your Catalyst project,
   then fill in the `CATALYST_*` vars in `.env` (see `.env.example`) — needed because
   `scripts/seed.js` runs outside a web request and can't use `server.js`'s
   per-request `catalyst.initialize(req)`.
6. **Seed data**: `npm run db:seed:catalyst`
7. **Verify the ZCQL assumptions**: this migration made two documented, unverified
   assumptions (see comments in `lib/zcql.js` and the individual `lib/*.js` files) —
   `executeZCQLQuery`'s exact row shape, and that ZCQL doesn't reliably support
   JOIN/GROUP BY (worked around by fetching flat + joining in JS everywhere). Run the
   app locally against your real project (`catalyst serve` or `npm run dev` with
   `CATALYST_*` env vars wired) and check one page (e.g. `/dashboard`) before trusting
   the rest.
8. **Local dev/test with Catalyst**: `catalyst serve` runs a local emulator that injects
   the headers `catalyst.initialize(req)` needs — use this instead of plain `next dev`
   once your project exists, or requests will hit the "Catalyst SDK failed to
   initialize" guard in `server.js`.
9. **Deploy**: `catalyst deploy` (or push, once Pipelines is set up — see below).
10. **Domain Mappings**: Catalyst Console → your AppSail service → Domain Mappings —
    point your custom domain at it; Catalyst handles SSL. Straightforward, console-driven,
    no code changes needed.
11. **SmartBrowz**: no setup needed beyond your project existing — `lib/pdfReport.js` calls
    `app.smartbrowz().convertToPdf()` directly, no separate table/config required.
    Verify the "Download Intelligence Report" button on `/dashboard` once you have a
    real project (its `Readable`-stream return type is confirmed from the SDK's own
    `.d.ts` files, but hasn't been exercised against a live PDF render yet).
12. **Pipelines (CI/CD)**: set this up via the Catalyst Console's pipeline creation UI
    (link your GitHub repo, pick "Deploy to AppSail" as the target) rather than
    hand-authoring the YAML — Catalyst's own docs only show a confirmed example for a
    Java/Maven pipeline, not Node.js, and the console UI generates a schema-correct YAML
    for you instead of guessing at unconfirmed keys.
